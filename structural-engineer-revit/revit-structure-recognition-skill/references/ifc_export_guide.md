# Getting data out of Revit: IFC export (fallback path)

This is the fallback path — used when no live MCP connection is available at all (including most cloud/sandboxed sessions, which have no network route to a process on someone's desktop) or when neither `mcp-server-for-revit-python` nor Autodesk's official Revit Public MCP Server is set up yet. If either MCP path is available, prefer it — see `references/mcp_pyrevit_python_guide.md` or `references/mcp_autodesk_official_guide.md`. What follows was originally written when IFC was this skill's primary path; the export settings below are still accurate, just no longer the first thing to reach for.

## MCP, for context

`references/mcp_pyrevit_python_guide.md` and `references/mcp_autodesk_official_guide.md` cover the two live paths in detail and are the more current sources — written from directly reading the relevant repo/documentation, not general awareness of the landscape. In short: both require something running on the engineer's own machine alongside a live Revit session, so neither is reachable from a sandboxed environment with no route to someone's desktop — which is exactly the situation IFC export exists to cover. Where IFC still earns its place even when an MCP path *is* available: a deterministic file the engineer can archive alongside the calculation package as a QA trail ("the recognition step ran against *this exact* file"), independent of whichever MCP server happens to be connected that day.

## Revit export settings that matter

From **File → Export → IFC**, or **Export Setup** for a saved configuration:

- **Schema: IFC4** (not IFC2x3) where the office standard allows it — IFC4 carries materially richer semantics for this skill's purposes (direct `PredefinedType` on occurrences, profile-based material definitions for steel sections, better property set support). If the office IFC standard mandates IFC2x3 Coordination View for deliverables, that's fine for other purposes, but export a separate IFC4 copy for this pipeline if possible.
- **Export Revit property sets** — must be enabled. This is how Revit-native parameters (a wall's `Function` value, for instance — the single most reliable signal this skill has for the retaining/shear/foundation distinction) survive into the IFC file as property sets. Without it, the skill is working from geometry and material alone, which is exactly the situation the classification heuristics are built to handle gracefully — but the native parameter, when present, is worth far more than any geometric inference.
- **Structural Analytical Model.** Revit maintains a separate analytical model (centerlines, node points, releases) alongside the physical one. Confirm it's built and enabled — **Manage → Structural Settings → Analytical Model**, and each structural element's own "Analytical Model" instance parameter — before exporting, and make sure the export options include the analytical/structural representation, not just the physical one. This is what gives `extract_ifc.py` a clean `Axis` representation (a two-point centerline) to read instead of having to infer a member's axis from solid geometry, which is slower and much less reliable. If the analytical model wasn't maintained during design, the extraction still works from the physical geometry, but expect more elements to fall back to insertion-point-only data and get flagged.
- **Category mapping** — confirm Structural Columns, Structural Framing, Walls, Structural Foundations, and Floors are all checked. Export setups built primarily for architectural coordination sometimes exclude categories this skill needs.
- **Coordinates** — export relative to the **Project Base Point** with shared coordinates applied consistently across linked models, if any. A mismatched Survey Point vs. Project Base Point is a common source of huge or oddly-offset global coordinates that will confuse the grid-resolution step; if `resolve_grid_story.py` reports elements sitting absurdly far from every grid line, this is the first thing to check.

## If only a `.rvt` file is available and export isn't possible right now

Ask for the IFC export rather than guessing at the model from drawings or a PDF — this skill's entire reliability model depends on structured geometry and semantics that a drawing set doesn't carry. If a live MCP connection genuinely is available in the session, it can substitute for individual element lookups, but treat it as filling gaps in a partial extraction, not as a replacement for running the full pipeline once export is possible.
